# 后羿 HOUYI 端到端自动化改造方案

> 目标：把「细菌名 → 端到端自动设计抗菌 binder」做成后羿模型本身的能力。
> 用户明确：不是一次性验证，而是做到真正端到端，任意细菌输入一键出结果。
>
> **✅ 2026-10-02 状态：本方案的 Phase 1-5 已全部落地，且已超越原方案（升级为十环纳米注射器设计平台）。下方 Phase 清单已回填完成度。**

## 现状诊断（2026-10-01）

| 环 | 现状 | 是否自动 |
|---|---|---|
| 环0 靶点分析 | 手动建知识库（金葡菌/结核杆菌都是手动） | ❌ 手动 |
| 环1 结构预测 | 手动在知识库里标 PDB | ❌ 半自动 |
| 环2 Binder 设计 | **空壳**，只读现成 binder 库，从不调 RFdiffusion | ❌ 假设计 |
| 环3 评分排序 | 只有 LengthScorer（长度优先），无真实折叠/序列质量 | ❌ 弱 |
| 环4 输出 | 已可输出 FASTA/JSON | ✅ 完成 |

核心结论：后羿目前是「靶点库复用器 + 现成 binder 排序器」，**没有真正的从头设计能力**。

## 目标架构（全自动端到端）

```
输入：细菌名（如 "Mycobacterium tuberculosis"）
  │
  ├─ 环0 靶点自动检索
  │    ├─ 路线A：UniProt 检索该菌 reviewed 蛋白 → 规则筛选（毒力/耐药/表面/必需）
  │    └─ 路线B：预置高质量靶点库（金葡菌15、结核杆菌11 已建）兜底
  │    产出：靶点知识库 + 全长序列（自动 fetch）
  │
  ├─ 环1 结构自动预测
  │    ├─ 有 PDB → 自动下载结构
  │    └─ 无 PDB → 自动 Chai-1 预测
  │
  ├─ 环2 真实 RFdiffusion 设计（新能力）
  │    ├─ 自动探测 PDB 链/残基号 → 构建 contig
  │    └─ 调用 run_inference.py 生成 binder 骨架（WSL protein_design env）
  │
  ├─ 环3 真实评分（新能力）
  │    ├─ ProteinMPNN 序列设计（多温度采样）
  │    └─ ESM-2 折叠质量评分（composite score）
  │
  └─ 环4 输出 Top binder（已有，保持）
```

## 关键技术约束（已踩坑，务必复用）

1. RFdiffusion 用 **protein_design** 环境（rfdiffusion_pvc 缺 omegaconf/hydra）
2. contig 残基号必须用 PDB **实际残基号**（探测自 PDB，非 1-N）
3. 跑前删 stale schedule pkl
4. 速度：每骨架 ~1.5 min（RTX 4070 Ti SUPER）
5. WSL 内存纪律：任务完成后 `wsl --shutdown` 释放 16GB
6. PowerShell 传 WSL 命令易被转义破坏，复杂逻辑写 .sh/.py 脚本文件再执行
